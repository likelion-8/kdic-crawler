# 7월 30일 스탠드업 미팅

## 전일 진행 사항

### 1. Intent 분류기 개선 및 최종 방식 확정

* 기존 질문 임베딩과 참조 질문의 코사인 유사도를 비교하는 1-NN 방식의 한계 확인
* 같은 페이지에서 생성된 유사 질문이 평가 참조 데이터에 포함되는 문제를 확인하고 Leave-Page-Out 방식으로 재평가
* 정보성·민원성 Intent 분류 방식별 성능 비교

| 방식                               |    정확도 |
| -------------------------------- | -----: |
| 1-NN 자기참조                        | 100.0% |
| 1-NN Leave-One-Out               |  88.8% |
| 1-NN Leave-Page-Out              |  80.5% |
| Centroid                         |  73.8% |
| 규칙 기반                            |  91.5% |
| 형태소 TF-IDF + Logistic Regression |  89.6% |

* 규칙 기반은 라벨 생성에 사용한 표현과 평가 규칙이 겹쳐 성능이 낙관적으로 측정됐을 가능성이 있다고 판단
* Kiwi 형태소 분석 결과를 TF-IDF 특징으로 변환하고 Logistic Regression으로 분류하는 방식 최종 채택
* 기존 1-NN Leave-Page-Out 대비 정확도 `80.5% → 89.6%`로 `9.1%p` 개선
* BERT 파인튜닝은 현재 데이터 규모와 CPU 학습 비용을 고려해 추후 검토하기로 결정
* 운영 Intent 모델 학습 스크립트 및 모델 파일 생성

  * `src/train_intent_morpheme.py`
  * `data/intent_classifier/tfidf_vectorizer.pkl`
  * `data/intent_classifier/logreg_model.pkl`
* `src/query_classifier.py`의 `classify_intent()`를 형태소 TF-IDF 기반 방식으로 교체
* `BusinessFunctionClassifier` 관련 미사용 코드와 앱 워밍업 제거
* 기존 `pipeline.py`, 검색 로직, Qdrant 및 캐시 구조를 변경하지 않고 정상 작동하는지 확인
* 신청·위임장 질문은 `civil_petition`, 제도 설명·보호 한도 질문은 `informational`로 분류되는 것을 확인
* 빈 문자열, 인사말, 범위 밖 질문에서도 크래시 없이 유효한 라벨이 반환되는 것을 확인

### 2. 복합 질문 분해 및 검색 구조 구현

* 하나의 질문에 여러 정보 요구가 포함되면 질문 전체가 하나의 임베딩으로 변환되어 검색 결과가 희석되는 문제 확인
* 복합 질문을 독립적인 하위 질문으로 분리하는 `query_decomposition.py` 구현
* 접속사, 복수 물음표, 쉼표와 질문형 어미 등의 신호로 복합 질문 후보를 먼저 탐지하는 구조 적용
* 복합 질문 신호가 확인된 경우에만 HyperCLOVA X를 호출해 불필요한 LLM 호출을 줄이도록 설계
* 단순 마침표나 정규식으로 분리하기 어려운 나열형 질문을 처리하기 위해 실제 분해는 LLM이 담당하도록 결정
* 하위 질문마다 다음 과정을 독립적으로 실행하도록 `pipeline.py` 구조 수정

```text
하위 질문
→ 질문 유형 및 Intent 분류
→ 검색
→ 근거 확인
→ 답변 또는 NO_SOURCE 처리
```

* 기존 단일 질문 처리 로직을 `_answer_one()`으로 분리해 재사용
* 단일 질문은 기존 파이프라인과 동일한 경로로 실행되도록 유지
* 최종 답변은 추가 LLM 호출 없이 하위 질문별 답변을 결정론적으로 결합하도록 구현
* LLM을 이용한 답변 재조립 과정에서 URL이나 내용을 임의로 생성할 위험이 있어 추가 조립 호출은 제외
* 복합 질문 평가용 데이터셋 생성

  * `data/testset/testset_compound.jsonl`
  * 복합 질문 15개
  * 범위 안 하위 질문 27개
* 복합 질문 원문 검색과 하위 질문 분해 후 검색 결과 비교

| 지표        |  분해 전 |  분해 후 |
| --------- | ----: | ----: |
| Recall@5  | 0.556 | 0.778 |
| MRR       | 0.334 | 0.568 |
| Recall@20 | 0.963 | 0.963 |

* 짧게 분리된 하위 질문에서 업무 맥락이 사라지면 검색 순위가 하락하는 문제 확인
* 분해 프롬프트에 생략된 업무명과 대상 맥락을 보존하도록 규칙 추가
* 맥락을 과도하게 추가하면 일부 질문의 검색 성능이 오히려 하락하는 반대 사례도 확인
* 테스트셋의 일부 정답 문서 라벨 오류 가능성을 확인하고 `confidence: low`로 표시
* 표나 라벨 위주로 구성돼 서술형 문장이 부족한 페이지는 질문 분해만으로 검색 성능을 개선하기 어렵다는 점 확인

### 3. 복합 질문 기능의 미완료 범위 확인

* 현재 검색 성능 개선 수치는 사람이 정리한 하위 질문을 이용해 측정한 결과임을 확인
* 실제 `decompose_query()`가 HyperCLOVA X를 이용해 질문을 올바르게 분해하는지는 아직 검증하지 않음
* 실제 LLM 분해 과정에서 다음 항목에 대한 추가 확인이 필요함

  * 원래 질문의 요청 사항 보존
  * 질문 항목 누락 여부
  * 불필요한 세분화 여부
  * 업무 맥락 보존 여부
  * 원문에 없는 정보 추가 여부
* 하위 질문별 최종 답변과 출처를 결합했을 때 자연스럽게 읽히는지 확인 필요
* 범위 안 질문과 범위 밖 질문이 함께 포함된 혼합형 질문에 대한 검증 필요

예시:

```text
착오송금 반환지원은 어떻게 신청하고,
보이스피싱범도 잡아줄 수 있나요?
```

* 첫 번째 질문은 공식 근거를 이용해 답변
* 두 번째 질문은 제공 범위 밖 또는 확인 가능한 근거가 없음을 별도로 안내하도록 검증 필요

### 4. Reranker 검증 일정 조정

* Reranker CPU 적용 시 검색 품질은 개선됐지만 문항당 처리 시간이 약 96초로 실서비스 적용이 어렵다는 점 확인
* GPU 환경에서 다음 모델을 비교하는 실험 계획 수립

  * `dragonkue/bge-reranker-v2-m3-ko`
  * `BAAI/bge-reranker-v2-m3`
* FP32·FP16, 후보 수 5·8·10·15·20 조건별 품질과 속도를 비교하기로 결정
* GPU 실험 환경이 다음 주 제공될 예정이므로 현재 단계에서는 최종 결과 정리를 보류
* GPU 검증 전까지 현재 AI Baseline에서는 Reranker를 기본 Off 상태로 유지
* GPU 실험 결과는 현재 서비스 개발을 막지 않는 별도 개선 후보로 관리하기로 결정

* `testset_compound.jsonl`의 복합 질문을 실제 `decompose_query()`에 입력

  * 출처 정확성
