## 금일 진행할 사항

오늘은 어제 논의한 내용을 실제 실험으로 확인하면서 **Grounding verifier와 남아 있는 게이트들의 적용 여부를 수치로 결정하는 것**을 우선한다.

### 1. Grounding verifier 실험

현재 구조:

```text
HCX 답변 생성
→ validate_answer LLM 검증
→ 최종 답변
```

검토 중인 구조:

```text
HCX 답변 생성
→ 결정론적 Grounding verifier
   ├─ 확실히 안전한 답변 → validate_answer 생략
   └─ 애매하거나 이상한 답변 → 기존 validate_answer 실행
```

오늘은 바로 운영에 적용하기보다 **실제로 스킵 가능한 답변을 얼마나 정확하게 골라낼 수 있는지 실험**한다.

* 답변에서 숫자·금액·비율·날짜 등 추출
* 답변의 수치가 검색 context에 실제 존재하는지 비교
* `[SOURCE_USED]` / `NO_SOURCE` 마커 함께 확인
* Grounding verifier가 PASS로 판단한 답변을 기존 `validate_answer`에도 넣어 결과 비교
* verifier PASS인데 LLM 검증에서 문제가 있다고 나온 케이스 집중 확인
* 안전성이 확인되기 전까지는 실제 LLM 검증을 끄지 않고 섀도 모드로 검증

확인할 지표:

* verifier PASS 비율
* PASS 중 `validate_answer` 정상 판정 비율
* PASS인데 `appropriate=false` 또는 근거이탈로 잡힌 비율
* 답변당 LLM 호출을 실제로 얼마나 줄일 수 있는지

---

### 2. 답변 매핑 게이트 수정

* 현재 답변 매핑이 적용되는 위치와 조건 다시 확인
* 매핑된 답변이 이후 불필요하게 플래너·검색·생성 단계로 넘어가는 경우가 없는지 확인
* 답변 매핑 → 캐시 → 플래너 순서에서 게이트 동작 정리
* 매핑 답변에 대해서도 출처·검증 처리가 필요한지 케이스별 확인

---

### 3. OOS 게이트 추가 준비 및 실험

어제 논의한 게이트 구조를 바탕으로 실제 적용 범위를 좁힌다.

```text
질문
→ 룰 기반 게이트
→ OOS 거리/유사도 게이트
→ 검색 relevance 게이트
→ 필요 시 supervisor
→ 답변 생성
```

* 인스코프 질문을 잘못 차단하지 않는 것을 최우선으로 설정
* 애매한 구간은 차단하지 않고 기존 RAG로 통과
* 바로 운영 판정을 내리지 않고 우선 로그만 남기는 섀도 모드 검토
* 기존 OOS 질문과 인스코프 질문을 함께 사용해 오차단 여부 측정

---

### 4. 0.35 임계값 재측정

재적재가 완료됐기 때문에 기존 인덱스에서 측정했던 `0.35`를 그대로 사용하지 않고 다시 측정한다.

* 인스코프 질문 검색점수 분포 확인
* OOS 질문 검색점수 분포 확인
* 두 분포가 실제로 어느 구간에서 갈리는지 확인
* 특히 **인스코프 질문이 임계값 때문에 잘리는 케이스** 확인
* 기존 0.35 유지 / 상향 / 하향 여부를 결과로 결정

단순 정확도보다 다음을 우선해서 본다.

```text
인스코프 오차단률
OOS 차단률
경계구간 질문 유형
```

### 5. 골든셋 검증 방식 정리

현재 골든셋이 분류기·검색의 참조 데이터와 평가 데이터 역할을 동시에 하면 자기참조 문제가 생길 수 있기 때문에 역할을 다시 확인한다.

* 참조셋과 실제 평가셋을 분리할지 결정
* 현재 evaluation dataset과 golden set의 중복 여부 확인
* OOS 평가 데이터 구성 방식 검토
* 신규 데이터 추가 시 평가셋에 바로 섞지 않는 방식 검토
* 이후 게이트·분류기 실험에서 동일한 평가 조건을 사용할 수 있도록 실험 방식 정리

* 멀티쿼리 질문에서 context가 과도하게 길어지는 경우 확인
* Grounding verifier가 비교할 **근거 context의 기준**도 함께 확정

### 7. 세션 기억 구조 검토

* 이전 대화 내용을 다음 질문에서 어느 정도까지 사용할지 결정
* 이전 질문 전체를 계속 전달하는 방식이 필요한지 검토
* 현재 질문만으로 검색할지, 이전 대화를 포함해 질의를 재작성할지 역할 분리
* 잘못된 이전 답변이 다음 답변의 근거처럼 이어지는 문제 방지 필요
* 세션 기억과 RAG 검색 context를 분리해서 관리하는 방향 검토

## Blocker / 논의 필요 사항

* Grounding verifier는 **수치가 context에 존재한다는 것만으로 답변 전체가 올바르다고 볼 수 없음**

  * 따라서 초기에는 `validate_answer`를 실제로 제거하지 않고 섀도 모드로 비교 필요
* `"5천만원"` ↔ `"50,000,000원"`처럼 표현이 다른 숫자의 정규화 범위를 정해야 함
* 숫자가 없는 일반 설명형 답변을 결정론적 verifier가 안전하게 PASS시킬 수 있는지는 별도 검토 필요
* OOS 게이트를 여러 개 동시에 활성화하면 어느 게이트 때문에 성능이 바뀌었는지 확인하기 어려움

  * 하나씩 추가하면서 인스코프 오차단률을 다시 측정하는 방식 필요
* 세션 기억을 그대로 검색 질의에 포함하면 이전 대화가 현재 검색 결과를 오염시킬 수 있으므로 검색용 문맥과 답변용 대화 문맥의 역할 구분 필요
