## 금일 진행할 사항

오늘은 대부분 **공통 작업**으로, 파이프라인 구조를 전원이 같은 수준으로 이해한 뒤 남은 게이트·검증 구조의 적용 여부를 결정하고 실험 순서를 확정한다.

### 1. 파이프라인 구조 리뷰 (공통)

* 흐름도 PDF 기준으로 이해 안 된 부분 이야기해보기 → 구조 파악
* `validate_answer` 3축(`used_source` / `kind` / `appropriate`)과 재생성 구제 흐름 정리
* 답변 매핑 → 질의 캐시 → 플래너로 이어지는 입구 층 확인

---

### 2. 관리자 [재적재] 실행 (공통)

표 청킹을 다시 하면서 재적재(pgvector 재임베딩)도 다시 했어야 했는데 누락된 상태다.

* 현재 불일치: DB pgvector **494청크(옛 청킹)** vs 로컬 BM25 **503유닛(새 청킹)**
* 위험 1 — 재청킹된 페이지를 건드리는 질문은 dense가 반환한 id가 로컬에 없어 **검색 RuntimeError** 가능 (`retrieval.py`의 명시적 가드)
* 위험 2 — id는 같은데 경계만 달라진 청크는 옛 텍스트 점수에 새 텍스트가 붙는 **조용한 정확도 왜곡**
* 재적재를 실행하면 관리자 [재적재] 버튼 + 홀드아웃 게이트(`index_gate`, Recall@5 기준 통과 시에만 반영)가 실제로 잘 도는지도 같이 확인된다
* 재적재 후 표 관련 질문 재평가 (질의 캐시는 인덱스 버전 대조로 자동 무효화됨)

---

### 3. 임계값 0.35 실험 다시 하기 — **재적재 후에**

* ⚠️ 순서 중요: 0.35는 옛 청킹 인덱스에서 실측한 값이라, 재적재로 점수 분포가 바뀌면 무효가 된다. **재적재 → 실험** 순서 고정
* Langfuse top5 최근접 span 로그로 인스코프 vs OOS 점수 분포를 먼저 뽑으면 임계값 논의를 숫자로 시작할 수 있음

* 5라벨 정확도 0.6456이지만, 라우팅에 쓰이는 건 **link_guide 여부 하나뿐** (link_guide → Hybrid, 나머지 전부 Dense)

### 6. 다른 게이트들 붙일지 결정

* 캐스케이드 설계 공유: 룰베이스(인사 패턴 — 금칙어 절반은 가드레일로 구현됨) → 코사인 극단값(OOS 전용, s_in 주신호) → 검색점수(기존 `gate_low_relevance`) → supervisor 3-way(ANSWERABLE/OOS/근거부족)
* 원칙: 중간 게이트는 극단값만 자르고 애매하면 통과 · 오차단은 곱으로 쌓임 · 임계값은 `get_param`(DB)
* 진행 순서: **베이스라인 측정 먼저** (`eval_pipeline_generation` — OOS 적절거절률·인스코프 오거절률) → supervisor → 앞단 게이트, 단계마다 재측정
* supervisor 도입 시 validate_answer와 역할·호출 수 정리 필요 (+2콜 문제 ↔ 아래 7번이 완충)

### 7. Grounding verifier(결정론 사전검사) 결정

**지금 (모든 답변 동일):**

```
HCX 생성 (1콜) → validate_answer LLM 검증 (1콜) = 답변당 항상 2콜
```

**수정안 (답변에 따라 갈림):**

```
HCX 생성 (1콜) → [정규식 검사 — 0콜, 수 ms]
   ├─ 깨끗함 (수치 전부 근거에 있음 + 마커 SOURCE_USED)
   │     → LLM 검증 건너뜀 → 바로 출처 부착      = 1콜
   └─ 의심스러움 (수치 불일치, 또는 NO_SOURCE, 또는 근거 없음)
         → 지금처럼 validate_answer LLM 검증      = 2콜 (기존과 동일)
```

* 검증을 없애는 게 아니라 **확실히 깨끗한 답변만 건너뛰는** 것 — LLM 검증(validate_answer)은 유지
* 스킵 안전 근거: [SOURCE_USED] 마커 오판 0/28 실측 + 문자열 대조는 세부 수치 오류를 LLM보다 확실히 잡음
* 결정 3개: ① 도입 여부 ② 섀도 모드 활성화 기준(스킵 대상을 LLM이 어떻게 판정했나 불일치율 기준) ③ 담당·범위(정규식 추출 + 수치 정규화 + `get_param` 스위치 + observation 필드)
