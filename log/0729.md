### 3. 복합 질문 분해 및 Multi-Query 검색 실험

* 사용자가 하나의 문장에 여러 질문을 함께 입력했을 때, 질문을 독립적인 하위 질문으로 분리하는 방식 검토
* 질문에 포함된 요청 사항과 정보 요구를 누락하지 않도록 하위 질문 생성
* 원본 질문과 분리된 하위 질문 간 의미 일치 여부 확인
* 단순한 단일 질문은 불필요하게 분해하지 않도록 복합 질문 판별 기준 설정

예시:

```text
예금보험금 신청 방법과 필요한 서류, 처리 기간을 알려주세요.
```

```text
하위 질문 1: 예금보험금은 어떻게 신청하나요?
하위 질문 2: 예금보험금 신청에 필요한 서류는 무엇인가요?
하위 질문 3: 예금보험금 처리 기간은 얼마나 걸리나요?
```

* 각 하위 질문을 개별적으로 검색
* 하위 질문별 검색 결과와 출처를 별도로 관리
* 같은 문서가 여러 하위 질문에서 검색될 경우 중복 문서 제거
* 각 하위 질문에 대한 답변이 빠지지 않도록 최종 답변을 항목별로 조립
* 서로 다른 업무가 포함된 복합 질문 처리 방식 검토

예시:

```text
예금보험금 신청 방법과 착오송금 반환 신청 조건을 알려주세요.
```

* 예금보험금 안내와 착오송금 반환 신청을 각각 검색

* Business Function을 검색 하드 필터로 사용하지 않고, 분리된 질문별로 전체 검색 수행

* 근거가 확인된 하위 질문만 답변하고, 근거가 없는 항목은 별도로 안내

* 필요할 경우 각 하위 질문을 의미가 동일한 여러 검색 질의로 확장하는 Multi-Query 방식 추가 검토

* 다음 방식을 비교

  * 원본 질문을 그대로 한 번 검색
  * 복합 질문을 하위 질문으로 분리한 후 개별 검색
  * 하위 질문 분리 후 각 질문에 Multi-Query 적용

* 다음 항목 측정

  * 하위 질문 분리 정확도
  * 질문 항목 누락률
  * MRR
  * Recall@5
  * 검색 시간
  * 질문 분해 및 질의 확장 시간
  * 전체 응답 시간

* 분리 과정에서 의미가 변경되거나 질문이 누락된 사례 분석

* 단일 질문과 복합 질문을 구분하여 실제 파이프라인 적용 여부 결정


### 4. 관리자 기능 범위 및 구현 계획 논의

#### 현재까지 정리된 기본 구조

```text
corpus.jsonl
→ chunks_all.jsonl
→ Dense·BM25 캐시
→ Qdrant 검색 인덱스
```

* Create·Delete 작업은 우선 `corpus.jsonl`에만 반영

* BERT의 정확도 향상과 모델 로딩 및 추론 시간을 함께 고려해야 함

## 홍주영

### Yesterday

* 질문 유형별 최종 검색 구조 확인
* `link_guide` Linear Fusion 적용 방식 검토
* Dense 검색과 Hybrid 검색의 파이프라인 연결 상태 확인
* 검색 성능 개선을 위한 추가 방식 검토

### Today

* Multi-Query 검색 방식 설계
* 사용자 질문에서 검색용 확장 질의를 생성하는 프롬프트 작성
* 원본 질문을 포함한 질의 확장 구조 구현
* 확장 질의 수에 따른 검색 성능과 처리 시간 비교
* 각 질의의 검색 결과 중복 제거
* RRF 및 점수 기반 결합 방식 비교
* 기존 단일 질의 검색과 Multi-Query 검색 성능 비교
* MRR, Recall@5 및 전체 응답 시간 측정
* 성능이 악화되는 질문과 잘못 확장된 질의 분석
* Multi-Query 파이프라인 적용 여부 결정
* 적용 시 기존 질문 유형별 검색 라우팅과 연결

### Blocker

* 확장 질의가 원본 질문의 업무나 의도를 변경할 수 있음
* 질의 생성 과정에서 LLM 호출 시간이 추가됨
* 검색 결과 결합 방식에 따라 성능 차이가 발생할 수 있음
* 단순한 질문에는 Multi-Query가 불필요한 지연을 추가할 수 있음
