## 2. 가장 중요한 것 — 운영 반영 경로가 둘 다 막혀 있었다

기획서의 3단계(초안 → 평가 → **게이트 통과 시 반영/게시**)에서 AD-007·AD-008 모두 ③ 도달 불가였다.

| | 원인 | 조치 | 검증 |
|---|---|---|---|
| AD-007 | 프론트가 서버 시그니처(sha256)를 `JSON.stringify` 와 비교 → 영구 stale. **목이 프론트의 틀린 가정에 맞춰져 있어 목에서만 통과** | stale 판정을 '평가 시점 스냅샷 값 비교'로 교체, 목은 opaque 해시 + 실서버 키 7종으로 정렬 | pnpm verify · 로직 단순화로 회귀 불가 |
| AD-008 | ① 평가가 운영보다 엄격(운영엔 있는 source_check 마커 복구가 평가에 없음) ② temperature 0.2 비결정 ③ 표본 4에 100% 요구 | ① 평가에도 동일 복구 적용 ② 평가·Smoke 만 temp 0 + seed(운영 무변경) ③ 출처 부착 ≥3/4 + 실패 문항만 seed 재시도 | **무변경 초안 2회 평가 → verdict·판정 동일(4/4 통과)** — 종전엔 회차마다 뒤집혔음 |

## 3. 운영 사고 하나 — AD-006 [변경 반영]은 누르면 취소가 안 됐다

실행해 보니 851문항 × (OpenAI+HCX) = **1,702콜·1.5~3시간을 단일 HTTP 트랜잭션**으로 돌았고,
브라우저를 닫아도 서버는 계속 돌며 공유 Supabase 트랜잭션을 점유했다(코드 스스로
"HTTP 요청에서 부르지 말 것"이라 적어둔 함수를 부르고 있었다). **조치**: 버전 스냅샷만 커밋하고
측정은 워커(SMOKE_EVAL 잡, `targets[0]=run_id` 인계)로 넘김 + 생성 축은 30문항 표본.
→ **워커(src/worker.py)가 상주해야 재측정이 돈다. 배포 구성에 워커 프로세스를 넣을 것.**
