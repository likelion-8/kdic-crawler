### 1. 질문 1건당 LLM 비용 실측 감사

발표에서 사용할 토큰 / 비용 수치를 추정값이 아니라 실측값으로 확보하기 위해, Langfuse 관측 데이터와 `rag_runs` 기록을 결합하는 비용 감사 스크립트를 작성하고 실제 운영 데이터를 기준으로 비용을 계산했다.

08-26 ~ 08-28 웹 / DASH-002 기준 138건을 분석한 결과:

```text
조기 종료 포함 전체 평균     : 질문 1건당 약 2.24원
생성 단계까지 진행된 질문    : 질문 1건당 약 4.18원
단일 답변 (재생성 없음) 기준 : 질문 1건당 약 2.99원
```

집계 과정에서 다음 기준을 명확히 했다.

* 웹 토큰 관측이 존재하는 08-26 이후 데이터만 사용
* HCX-007이 섞인 112건은 비교 조건이 달라 제외
* 관측값이 0인 완료 건 69건은 "확인 불가"로 구분 (임의 추정하지 않음)
* 대화 원문 덤프는 저장소에 올리지 않고 `.gitignore` 처리, 재현 스크립트로 각자 재생성

이로써 발표에서 외부 평균값을 임의로 인용하지 않고, **실제 프로젝트 측정값을 기준으로 비용 효율을 설명할 수 있는 근거**를 확보했다.

### 2. 저장소 구조 정리

발표 및 저장소 공개를 앞두고 운영 코드와 실험 산출물이 섞여 있던 구조를 정리했다.

* 파이프라인이 사용하지 않는 코드 삭제 (개인 크롤러, 빈 파일, 미사용 Qdrant 색인기, 미사용 UI 프리미티브)
* 실험 스크립트 23개를 `experiments/`로 이동 — 운영 코드와 "결정의 근거"를 분리
* 실험 산출물을 `data/`에서 `results/`로 이동하고 색인(`results/README.md`) 정리 — `data/`에는 파이프라인 입력만 유지
* 일지를 `docs/worklog/`로 이동, README에 저장소 지도 추가
* 정리 과정에서 발생한 회귀 3건 수정 (색인기 문법 오류, 트레이스 오염, 덤프 ignore 구멍)

정리 후 경로를 변경한 실험 스크립트의 import 스모크 테스트를 통과했고, 운영 코드(`src` / `api` / `web`)는 변경하지 않았다.

발표 이후에도 프로젝트를 외부에서 이해할 수 있는 상태로 만들기 위해 저장소 문서를 정리한다.

* **연구계획서 작성** — 프로젝트 배경, 문제 정의, 실험 계획과 최종 구조 선택 과정을 문서로 정리
* **README 작성** — 프로젝트 소개, 최종 RAG 파이프라인 구조, 주요 실험 결과, 실행 방법 정리 (조직 프로필 README 초안 포함)
* **워크플로우 작성** — 데이터 수집부터 답변 생성까지의 전체 워크플로우를 문서로 정리

단순히 기능 목록을 나열하기보다, 저장소만 보고도

```text
어떤 문제를 정의했고
→ 어떤 실험을 했고
→ 왜 이 구조를 선택했는지
```

가 전달되도록 작성하는 것을 목표로 한다.
