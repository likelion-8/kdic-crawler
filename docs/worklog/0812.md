## 금일 진행할 사항

### 1. 변경 요청 감사 로그 연결

변경 요청 승인·반려 결과가 관리자 활동 로그에 남도록 연결한다.

구현 범위:

- ADD 승인·반려 로그
- DELETE 승인·반려 로그
- 관리자 ID 및 변경 요청 ID 기록
- 요청 종류별 action 분리
- 승인·반려 감사 로그 테스트

---

### 2. 개인정보 마스킹 공통 처리

관리자 대화 로그 조회 시 개인정보가 그대로 노출되지 않도록 공통 마스킹 함수를 구현한다.

구현 범위:

- 주민등록번호
- 전화번호
- 계좌번호
- 카드번호
- 이메일
- `None` 및 빈 문자열 처리
- 날짜·금액·수량·URL·`page_id` 과마스킹 방지

DB에는 원문을 유지하고 관리자 API 응답 직전에만 마스킹하도록 구성한다.

---

### 3. 대화 로그·피드백 조회 API 구현

`rag_runs`와 사용자 피드백을 관리자 화면에서 확인할 수 있도록 조회 API를 구현한다.

대상 API:

- `GET /api/admin/logs`
- `GET /api/admin/logs/summary`
- `GET /api/admin/logs/{request_id}`
- `POST /api/admin/logs/exports`

구현 범위:

- 질문 검색 및 Intent·Status·Feedback 필터
- 오늘 / 7일 / 30일 / 사용자 지정 기간 필터
- KST 기준 날짜 처리
- 페이지네이션 및 최신순 정렬
- 피드백 LEFT JOIN
- 질문·답변 개인정보 마스킹
- 오늘 대화 수 및 성공·실패·좋아요·싫어요 집계
- 상세 로그·오류·분류 결과 조회
- 권한 및 예외 처리

내보내기 API는 목록·요약·상세 구현 이후 시간이 남으면 진행한다.

---

### 4. RAG 파이프라인 개선 방향 구체화

4차 멘토링 피드백을 바탕으로 현재 파이프라인에서 우선 수정할 구조를 정리한다.

검토 방향:

사용자 질문  
→ Out-of-Scope 판단  
→ Query Planning / Retrieval  
→ Reference Validation  
→ 답변 생성

주요 검토 항목:

- 명확한 Out-of-Scope 질문 조기 제거
- `SOURCE / NO_SOURCE` 판단과 Reference Validation 역할 분리
- 답변 생성 전 `질문 + Reference` 기준 검증
- Validation용 청크 Summary / Metadata 활용
- Multi-Query가 필요한 질문에만 선택적으로 적용
- Reference Validation 실패 시 재검색 조건 및 최대 횟수
- Langfuse Trace 적용 범위 정리
