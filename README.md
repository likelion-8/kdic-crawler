## 1. Problem Definition

### 무엇을 해결하려는가

P2까지 만든 챗봇은 **돌아가지만 운영할 수 없다.**

답변 품질을 좌우하는 것은 두 가지다 — **적재된 데이터**와 **검색 파라미터**. 그런데 지금은 둘 다
코드에 있다. 새 안내 페이지가 생기면 개발자가 크롤러를 돌리고 적재 스크립트를 실행해야 하고,
Top-K를 5에서 3으로 바꿔보려면 `src/pipeline.py`의 상수를 고쳐야 한다. 실제로 P2가 남긴 상태가
그렇다 — `USE_RERANKER`·`USE_QUERY_DECOMPOSITION`·`USE_SOURCE_RECHECK`·`K_FINAL`이 전부 코드 상수다.

> **매 변경마다 개발자가 개입해야 하는 시스템은 운영되지 않는다.** 운영자가 데이터를 넣고,
> 파라미터를 바꿔보고, 그 변경이 품질에 어떤 영향을 주는지 **직접 확인할 수 있어야** 한다.

### 왜 어려운가 — 파라미터마다 반영 비용이 다르다

이 프로젝트의 설계를 가르는 핵심 구분이다.

| 구분 | 예시 | 반영 비용 |
|---|---|---|
| **검색 시점** 파라미터 | Top-K, 리랭킹 유무, Hybrid 결합비 | 질의 시 적용 → **즉시 비교 가능** |
| **적재 시점** 파라미터 | Chunk Size, 청킹 방식 | 변경 시 **기존 데이터 전체 재청킹·재적재** |

순진하게 만들면 파라미터를 하나 바꿔볼 때마다 494청크 전체 재적재가 돈다. 그래서 두 종류를
**다른 방식으로** 다뤄야 한다.

### 왜 지금 중요한가

P1·P2가 남긴 미완 과제 중 셋이 **관리 도구가 있어야 풀린다.**

- **E2E 정량 평가 부재** — P2가 잰 건 2026-07-30 베이스라인 1회뿐이고, 그 뒤 intent 교체·분해
  On·근거 재확인·pgvector 전환이 전부 미측정이다. 평가를 사람이 매번 손으로 돌리는 한 이 공백은
  반복된다.
- **파라미터 튜닝 보류** — "아직 이르다"며 미룬 이유 중 하나가 **바꿔보고 비교할 수단이 없어서**였다.
- **데이터 갱신 추적** — 원본 사이트는 바뀐다(공시이율 표는 매달). 갱신 감지는 `content_sha256`으로
  만들어 뒀지만, 재수집을 **누가 언제 트리거하고 결과를 어디서 확인하는지**가 없다.

## 2. Background & 현재 기준선

### 2.1 이미 만들어져 있는 것

P3는 백지에서 시작하지 않는다. 웹 서비스 골격과 관리자 화면은 이미 구현돼 있다.

| 영역 | 현재 상태 |
|---|---|
| 관리자 화면 | **48파일 12,409줄**, 화면 11개 + 리다이렉트 2개 (`web/src/routes/admin/`) |
| 챗봇 화면 | 웰컴·대화·오류 6종·역할 되묻기 (`web/src/routes/chat/`) |
| API 계약 | MSW 목이 **고유 엔드포인트 85개**(관리자 79 + 공개 6)를 처리 |
| 백엔드 | **3개뿐** — `GET /health` · `GET /api/health` · `POST /api/chat`(SSE) |
| 저장소 | Supabase Postgres(pgvector) — 7테이블 |

### 2.2 가장 큰 격차 — 관리자 백엔드가 0이다

`api/` 전체에 `admin` 문자열이 **0건**이다. 목이 정의한 관리자 79개 엔드포인트 중 구현된 것이
하나도 없다. 화면은 전부 **MSW 목 위에서만** 돈다.

DB도 마찬가지다. 실재하는 7테이블 중 관리자가 읽을 것은 절반뿐이다.

| 화면 | 읽을 테이블 | 상태 |
|---|---|---|
| AD-002 지식베이스 | `documents`(58) · `document_chunks`(494) | ✅ 실재 |
| AD-006 평가 | `evaluation_dataset`(851) · `test_set`(89) | ✅ 실재 |
| AD-005 대화 로그 | `rag_runs`(80) | ⚠️ 실재하나 **웹 대화는 안 쌓임** |
| AD-004 파이프라인 잡 | — | ❌ 없음 |
| AD-010 계정 · AD-011 활동 로그 | `admin_*` | ❌ 없음 |

**리포에 정의가 없는데 DB에 실재하는 테이블이 2개 있다** — `feedback`(0행)·`suggested_questions`(10행).
`src/schema.py`에도 어떤 `.py`/`.sql`에도 생성 경로가 없어 **재현이 안 된다.** P3가 먼저 정리해야 할 부채다.

### 2.3 P2에서 넘어온 계약 불일치

프론트와 백엔드를 목 없이 붙이면 지금은 **화면이 빈다.** `api/rag/sse.py`가 `event:` 라인 없이
`data:`만 보내는데 프론트 파서는 이벤트 이름으로 분기해서, `answer_delta`·`done`·`error`가 전부
버려진다. 이건 P3의 첫 관문이다.

## 3. Proposed Method

### 3.1 관리 대상과 화면 매핑

기업(클라비)이 정한 관리 범위 3종을 화면에 매핑한다.

| 관리 대상 | 화면 | 하는 일 |
|---|---|---|
| **검색 데이터** | AD-002 지식베이스 | 페이지·청크 조회, 신규 URL 추가, 검색 제외/포함 |
| **데이터 파이프라인** | AD-004 파이프라인 | 재수집·재적재 트리거, 6단계 진행 상태 |
| **RAG 파라미터** | AD-007 RAG 파라미터 | Top-K 등 변경, 변경 전후 비교, 운영 반영 |

여기에 P2가 남긴 공백을 메우는 화면을 더한다 — AD-005 대화 로그(실사용 관찰), AD-006 평가
(테스트셋 기반 정량 비교), AD-008 프롬프트·가드레일, AD-009 운영 정책, AD-010 보안·권한,
AD-011 활동 로그.

### 3.2 핵심 설계 1 — 적재 전에 확인하고 넣는다

신규 URL을 넣으면 곧바로 적재하지 않는다. **파싱 → 청킹 → 검증 4단계를 미리 돌려 결과를 보여주고,
사람이 확인한 뒤에만 적재**한다(AD-003, AD-002 안의 인라인 블록).

잘못 잘린 청크나 누락된 메타데이터를 **적재 전에** 걸러내기 위해서다. P1에서 표가 잘리면
AnswerRecall이 0이 되는 걸 이미 봤다 — 그 실패를 운영 중에 다시 겪지 않으려면 미리 보는 수밖에 없다.

미리보기는 **운영에 영향 없는 앞 4단계까지만** 실행한다. 색인·반영(5·6단계)은 적재 후에 이어서 돈다.

### 3.3 핵심 설계 2 — 파라미터를 반영 비용으로 나눠 다룬다

| | 검색 시점 (Top-K·리랭킹·결합비) | 적재 시점 (Chunk Size·청킹 방식) |
|---|---|---|
| 비교 방법 | **운영 인덱스에 그대로 두 설정 질의** → 나란히 비교 | **테스트용 소량 재적재** 후 비교 |
| 반영 | 즉시 | 결정 시에만 전체 재적재 |

적재 시점 파라미터를 소량으로 비교하려면 **소량 테스트가 전체를 재현해야 한다.** 그래서 테스트
데이터에 **Hard Negative**(타 업무의 유사 문구 청크)를 원본 분포대로 포함한다. P1이 측정한
"top-1의 25.4%가 타 업무" 혼입이 바로 그 분포다 — 이걸 빼고 소량 테스트를 하면 실제보다 좋게 나온다.

> 재현성이 확보되어야만 전체 재적재 없이 소량 비교로 반영 여부를 판단할 수 있다.

### 3.4 핵심 설계 3 — 변경은 3단계를 거친다

파라미터·프롬프트 변경은 바로 운영에 나가지 않는다. **①초안 편집 → ②초안 평가 → ③운영 반영**
순서를 강제하고, **최신 평가가 게이트를 통과해야 [운영 반영]이 열린다.** 초안을 고치면 평가가
무효화된다.

P1·P2에서 "평균 점수가 올라도 민원·범위 밖 질문에서 치명적 오류가 늘면 반영하지 않는다"는 기준으로
업무 필터와 리랭커를 걸러냈다. **그 기준을 사람의 판단이 아니라 화면의 게이트로 만드는 것**이
P3가 하는 일이다.

### 3.5 핵심 설계 4 — 위험 작업은 사유를 남기고 되돌릴 수 있게

관리자 작업은 데이터를 바꾼다. 되돌릴 수 없는 것과 되돌릴 수 있는 것을 구분해 통제한다.

- **모든 쓰기**에 멱등키(`request_id`) 필수 — 같은 요청이 두 번 들어가도 두 번 실행되지 않게
- **위험 작업**은 확인 모달에서 **변경 사유** 필수, 결과를 활동 로그에 남김
- **되돌리기 어려운 3종**(전체 캐시 비우기 · 계정 권한 변경 · 긴급 롤백)은 **비밀번호 재확인**
- 활동 로그는 **추가 전용** — 수정·삭제 API를 만들지 않는다
- 원문 직접 수정은 **지원하지 않는다** — 재크롤링하면 사라지므로 고칠 수 있게 하면 거짓말이 된다

### 3.6 권한 모델

`VIEWER(0) < OPERATOR(1) < EDITOR(2) < ADMIN(3)` 4단 서열이다.

| 역할 | 할 수 있는 일 |
|---|---|
| VIEWER | 조회 전용 |
| OPERATOR | 파이프라인 실행·취소·재시도, 질의 캐시 관리 |
| EDITOR | 초안·콘텐츠·테스트셋·설정 편집, 게시, 적재 |
| ADMIN | 전체 캐시, 롤백, 계정 관리 |

화면 숨김은 편의일 뿐 **최종 판정은 서버 403**이다. 프론트가 감춘 것을 보안으로 여기지 않는다.

## 4. Experiment Design

관리 도구는 "동작한다/안 한다"로만 볼 수 없다. **운영자가 내리는 결정이 실제로 나아지는가**를 본다.

| 실험 | 질문 | 측정 |
|---|---|---|
| **A1** | 소량 테스트가 전체를 재현하는가 | 같은 파라미터 변경을 소량 세트와 전체 851문항에서 각각 평가해 **순위 일치도**와 MRR 차이 |
| **A2** | Hard Negative 비율이 재현성을 좌우하는가 | 타 업무 청크 비율 0% / 실제 분포 / 과다 세 조건에서 A1을 반복 |
| **A3** | 미리보기가 불량 적재를 막는가 | 의도적으로 잘리는 페이지(대형 표·FAQ)를 넣어 **적재 전 발견율** |
| **A4** | 게이트가 나쁜 변경을 막는가 | P1에서 이미 폐기된 설정(업무 필터 On, 리랭커 On)을 초안으로 넣고 **게이트가 반려하는지** |
| **A5** | 파라미터 변경이 품질에 주는 영향 | Top-K 3/5/10, 분해 On/Off, 근거 재확인 On/Off의 전후 비교 |

**A4가 특히 중요하다.** P1·P2가 실측으로 폐기한 설정을 시스템이 스스로 걸러내지 못하면, 이 도구는
사람의 판단을 대체하는 게 아니라 **나쁜 결정을 빠르게 반영하는 장치**가 된다.

### Evaluation Metrics

- **검색 품질**: Recall@1/3/5, MRR, AnswerRecall@5 — P1 기준 그대로
- **답변 품질**: 정답성(LLM-as-a-judge), 출처 정확도, 환각률, 거절 품질 — **P2가 못 한 것을 여기서 한다**
- **운영 지표**: 적재 전 불량 발견율, 파라미터 변경 리드타임, 재적재 없이 판단한 비율

평가셋은 `evaluation_dataset`(851)을 전체 평가로, `test_set`(89 held-out)을 Smoke 회귀로 쓴다.

| 관리자 백엔드 79개를 다 만들 시간이 없다 | P0 범위를 데이터·파이프라인·평가로 좁힌다. 나머지는 목을 유지해 화면은 살려 둔다 |
| E2E 평가 재도입이 늦어진다 | 검색 지표만으로 먼저 게이트를 세우고 답변 품질은 뒤에 붙인다 |
| 소량 테스트가 전체를 재현하지 못한다 | A1·A2로 먼저 확인한다. 재현이 안 되면 **적재 시점 파라미터는 전체 재적재로만** 판단하도록 범위를 줄인다 |
| 리포에 정의 없는 테이블(`feedback`·`suggested_questions`) | `src/schema.py`에 정의를 되살려 재현 가능하게 만든다 — P0 착수 전 정리 |
| 관리자 조작이 운영 데이터를 깬다 | 사유 필수 + 활동 로그 + 되돌리기 어려운 3종 재인증. 원문 직접 수정은 아예 막는다 |

## 9. 완료 기준

- 목(MSW)을 끄고 실제 백엔드로 챗봇과 관리자 주요 화면이 동작한다.
- 신규 URL을 관리자 화면에서 넣어 **미리보기 → 적재 → 재색인 → 검색 반영**까지 한 번에 이어진다.
- 파라미터를 바꿔 **전후 검색 품질을 화면에서 비교**하고, 게이트를 통과해야 운영에 반영된다.
- 모든 위험 작업이 사유와 함께 활동 로그에 남는다.
- P1·P2가 폐기한 설정(업무 필터·리랭커)을 초안으로 넣으면 **게이트가 반려한다**.
